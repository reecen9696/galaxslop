# Review of the plan, 2026-10-12

Scope: `README.md`, `AGENTS.md`, `TASKS.md`, `docs/*`, the skill, and the
Petari tree in `decomp/`, checked against the actual GalaxyQuest, SMGwebport
and smg-online repositories. Outcome: the route is right; six specifics in
the plan were wrong and would have cost weeks. Each became a decision
(D-007 to D-013) and a task change. This file is the why; `DECISIONS.md`
is the what.

## What holds up

- Petari -> Emscripten with a GX layer is the only route that gives five
  independent clients. Petari is 100% code for all four regions (its CI
  builds RMGJ01, RMGE01, RMGP01, RMGK01). The game calls GX, JSystem, nw4r
  and the RVL SDK; the SDK sources are in `decomp/src/RVL_SDK/` and the
  port replaces `gx`, `os`, `dvd`, `nand`, `pad/wpad`, `ax/dsp`, `vi`, `thp`.
  GalaxyQuest has done exactly that replacement and all 44 galaxies load.
- Independent worlds + puppets + shared progress log is what smg-online
  ships (16 visible players, UDP relay, ordered resend log). Our NETCODE.md
  is the same model over WebSocket. Nothing to change in the protocol.
- Lanes, claim-on-main, one task per branch: fine for two agents.

## What was wrong, and the fix

1. **"GalaxyQuest's GLES layer maps 1:1 to WebGL2"** (D-002, BUILD_SPEC 5.2,
   SKILL 2). It does not. `gl_shadergen.cpp` emits `#version 320 es` with
   four shader storage buffers (`rows`, `recs`, `st`, `vtxRec`) read via
   `gl_VertexID`; `gl_renderer.cpp` uses `glVertexAttribFormat/Binding`,
   `glProgramBinary`, a compile thread on a shared EGL context, and a QCOM
   foveation hook. WebGL2 is ES 3.0 and has none of them. macOS OpenGL is
   4.1 and has no SSBOs either, so the planned native build on a Mac fails
   the same way. P0-08 "fix whatever breaks" hid the largest piece of work
   in the project. Fix: D-008, new task P0-10 on the critical path, with a
   concrete recipe (data textures + `texelFetch`, integer attribute,
   `glVertexAttribPointer`, GLSL source cache + `KHR_parallel_shader_compile`).
   One renderer then serves native and web. WebGPU stays a spike, but the
   premise "Safari behind flags" is stale (shipped 2025); pull P5-03 forward
   if the data-texture path costs more than ~2 ms.

2. **Vendoring GalaxyQuest's decomp onto newer Petari.** P0-02 took only
   `decomp/` from GalaxyQuest and P0-03 took `platform/` separately. Those
   were built together (`compat.h` force-include, hooks into platform
   symbols). The repo today holds raw Petari `8c5307d`, two weeks newer than
   GalaxyQuest's base, with renames (`ErrorArchive` -> `ErrorMessageArchive`)
   that would conflict with its patch. Fix: D-007, one snapshot of
   decomp + platform + cook at `d8a039c`; keep Petari's history in the repo
   and move the `petari-base` tag to the matching upstream commit so the
   port diff stays readable. Rebase onto newer Petari only when a specific
   fix is needed.

3. **Pyodide for the in-browser cooker** (D-006, P1-02) and "ISO/RVZ input".
   `cook.py` is stdlib-only, ~90 KB across 14 modules, uses a process pool,
   and GalaxyQuest added a `native/` hot path because pure Python was slow.
   Pyodide is single-threaded per worker and several times slower; a 10 min
   budget was fiction. It also reads only extracted folders, and Wii disc
   images are AES-encrypted (needs the user's common key), so "pick an ISO"
   was a second hidden project. Fix: D-009, TypeScript cooker in workers,
   `cook.py` as the byte-for-byte oracle, extracted folder via
   `showDirectoryPicker()` in Phase 1, disc images as P5-01 with the key
   caveat stated. P5-01 (Rust cooker) deleted.

4. **"Cloudflare free tier is enough"** (D-003, BUILD_SPEC 5.4, P3-05).
   150 messages/s per room is ~1.1M per 2-hour session; the free tier is
   100k requests/day, and Durable Objects would be a second server code
   path. Fix: D-010, Node container on a cheap host, same code as local.

5. **Progress merge into the player's save** (NETCODE "Progress merge",
   P3-02). Union-merging a friend's stars into a solo save is irreversible.
   Fix: D-012 proposal (co-op save namespace) and P3-00 to decide it before
   any merge code exists.

6. **Two `.bcsv` tables in `decomp/`.** Petari embeds `GalaxyID.bcsv` and
   `StoryEvent.bcsv` via `.incbin` in the Wii build. AGENTS.md bans `.bcsv`;
   GalaxyQuest excludes them and its cooker pulls them from the user's
   `main.dol`. Fix: D-011; the snapshot removes them, P0-02 confirms.

## Smaller corrections made

- Memory: BUILD_SPEC's "heap under 384 MB" conflicted with GalaxyQuest's
  fixed 0x80000000/0x90000000 window. D-013: keep the window for the spike
  (`-sMAXIMUM_MEMORY=4GB`), budget resident memory instead, relocate later
  if needed. macOS needs `-Wl,-pagezero_size,0x1000`.
- Threads: GalaxyQuest emulates OS threads in its own scheduler. The game
  is single-threaded; `PTHREAD_POOL_SIZE` is small. The skill said
  "threads (pthreads)" for `os/`.
- Textures: the skill claimed the cooker decodes to RGBA8/BC1 and that
  WebGL2 needs S3TC. The cooker keeps GX formats; the renderer decodes at
  load. Removed.
- SMGwebport: treated as a source of flags and a shader seed. It publishes
  neither source nor license; only a loader (`shell.js`) and packed data.
  It is proof of feasibility and a hint at an export surface, nothing more.
  Its seed is for a different shader generator.
- Regions: GalaxyQuest tested EUR and USA, not EUR only. `dol_tables.py`
  does not exist; the file is `dol_data.py`. `validate.py` already exists;
  P0-05 wires it as `--verify` and adds a manifest.
- Lane balance: Phase 0's critical path was all lane A (P0-03 -> 04 -> 06 ->
  08) while lane B idled. Native host/OS/disc work moved to B (its own
  directories anyway); A owns the renderer rework. Paths in AGENTS.md now
  follow GalaxyQuest's `platform/src/<subsystem>/` layout so its fixes can
  be pulled later.
- Language: C++17 -> C++20 (GalaxyQuest's CMake).
- CI honesty: a stub game folder of empty files proves platform init and a
  clean exit, not boot. The docs now say so; a null renderer gives CI a
  GL-free headless target.
- `THIRD_PARTY_NOTICES.md` pointed at `decomp/LICENSE-Petari.txt`; the file
  is `decomp/LICENSE`.
- `.gitignore`: `game/` unanchored matched `decomp/src/Game` on
  case-insensitive filesystems (3,200 files silently ignored). Anchored.

## Addendum: survey of how others build browser multiplayer from a ROM

Asked after the review: is decomp + Emscripten actually the best way, or
is there a route the plan missed? Checked every browser port of a
Nintendo game with online play that could be found, plus the emulator,
recompilation and streaming alternatives. Outcome: the route stands; the
GX layer changes (D-014); two more tasks (P0-00, P0-11).

**Browser multiplayer precedents, all the same shape.** sm64js (2020,
hand-ported SM64 to JS, Rust/Postgres MMO server, WTFPL), sh1ftmaker's
sm64coopdx web port (Emscripten, WebGL, PeerJS P2P, ROM cached in the
browser), metalfox-b/sm64-coop-web (Emscripten, Node WebSocket relay,
SQLite worlds, ROM hashed into IndexedDB, MIT), and Oliver Sauter's
12-player SM64 (sm64ex + coopdx, own ROM, voice/video). None bundle the
ROM, all do asset extraction client-side, all use a relay or WebRTC. Our
plan is this pattern applied to a Wii game.

**The GX layer is where the plan was weakest, and there is a better
option.** Aurora (encounter, MIT): used by AstroCore, Metaforce,
Dusklight, WiiCompiled; `lib/gx/command_processor.cpp` decodes hardware
FIFO opcodes with a per-array `le` flag; `include/dolphin/` provides SDK
headers; DVD via nod, THP decoder, CARD included. `webcompiled`
(GPL-3, 223 commits) builds WiiCompiled + Aurora with Emscripten 6.0.12
and emdawnwebgpu, JSPI instead of SharedArrayBuffer, ~60 fps Mario Kart
Wii races in Chrome on desktop. That is a stronger base than reworking an
AI-written GLES 3.2 renderer down to WebGL2, so D-014 makes Aurora primary
with a 3-week timebox and keeps D-008 as the fallback.

**Rejected with evidence (D-015):** `wasm-dolphin` (Wii on software
raster only, no Wii Remote), gecko/CubeDeck (interpreter), WiiCompiled as
the base (30-minute local recompile, opaque to mods), waiting for
AstroCore (no date). Cloud streaming is kept as the playtest baseline.
